# Личная коллекция, отсутствие регистрации и роли
## Первая версия без аккаунтов
Все публичные разделы и инструменты доступны немедленно. При первом личном действии создаётся локальный профиль UUID; форма регистрации не нужна. В настройках коротко объяснить «Коллекция хранится в этом браузере» и дать экспорт. Не обещать перенос между устройствами или восстановление после очистки браузера.

Основное хранилище — IndexedDB. localStorage содержит только небольшой набор настроек и указатель активного профиля; массивы коллекции туда не складывать. Структура DB: profiles, collectionEntries, presets, rebonusSessions, settings, migrationJournal, quarantine. Версия DB отдельна от версии игрового набора.

## Что означает «Пойман»
Флаг `everCaught` — пользователь уже получал это семейство. Это исторический факт из ручной отметки, не проверка игры. Он не означает, что существо сейчас в инвентаре и его можно сдать. Форма/эволюция учитывается в obtainedFormIds; поимка первой формы не включает сразу все четыре. Отметка семейства без выбора формы допускается.

`currentOwnedCount=null` означает количество не учтено. 0 означает пользователь явно сообщил отсутствие экземпляров. Для простого MVP текущий инвентарь не обязателен: на экране игровых наборов выводить «Известно/Поймано X изY», не «Можно сдать». Расчёт сдачи разрешён только при явно введённом наличии и количественных требованиях. `rewardClaimed` — отдельная ручная отметка, поимка всех членов не выдаёт награду автоматически.

Пример локальной записи:
```json
{
  "familyId": "miscrit:1",
  "everCaught": true,
  "obtainedFormIds": ["miscrit:1:form:1"],
  "currentOwnedCount": null,
  "favorite": true,
  "note": "Нужен отдельный RS",
  "updatedAt": "2026-09-15T12:00:00Z",
  "localRevision": 1,
  "deletedAt": null
}
```

Качество конкретного экземпляра хранится в build preset/instance, а не на уровне семейства: можно иметь одновременно S+ и RS. Пометка «идеальный» без выбранного качества и данных экземпляра не создаётся автоматически.

## Запись и синхронность интерфейса
Изменение сохраняется транзакцией, UI обновляется после успешной локальной записи либо оптимистично с откатом. Toast подтверждения включает Undo несколько секунд. Все экраны используют единый store, а не отдельные состояния captured по маршрутам. Для нескольких вкладок — BroadcastChannel и обновление из IDB. Транзакция читает последнюю ревизию перед изменением, чтобы не затереть соседнюю запись устаревшей копией массива.

При QuotaExceededError показать ошибку сохранения и экспорт; не рисовать будто запись сохранилась. При недоступности IDB можно работать в памяти с явным статусом «Изменения не сохраняются». Режим private может очищать данные после закрытия: текст о локальном хранении остаётся доступным. Ключи личных данных не включаются в публичный search index и service worker cache.

## Экспорт и импорт
Экспорт JSON: schemaVersion, exportId, exportedAt, sourceDatasetVersion, profile, entries, collectionClaims, presets. Без cookies, auth-токенов, истории поиска и технических секретов. Файл с безопасным именем `miscrits-collection-YYYY-MM-DD.json`.

Импорт максимум5 MiB, не больше10000 entries и1000 presets, текстовые поля с лимитами. Сначала parse+schema+reference validation, затем предпросмотр: сколько новых, изменённых, конфликтных и неизвестных. Выбор «Объединить» или «Заменить». Перед заменой предложить скачать резервную копию. Запись атомарна, не частичная по мере чтения.

Объединение требует явной политики: существующие записи с большей локальной ревизией не сравниваются с ревизиями другого профиля; timestamp другого устройства не считается абсолютной истиной. Для булевых отметок можно предложить сохранять объединение everCaught=true, obtainedFormIds=union, favorite по выбору. Снятые отметки/tombstone — конфликт, который пользователь видит. Пресеты импортируются под новыми UUID или сохраняют ID при идентичном содержимом. Неизвестные familyId идут в quarantine с сохранением исходной записи.

## Будущие роли
| Роль | Доступ | Где обеспечивается |
|---|---|---|
| anonymous | Каталог, карты, инструменты | Публичные read endpoints |
| local_guest | То же + собственные данные браузера | Локальное хранилище, без server identity |
| member | То же + синхронизация своих данных | Сервер проверяет владельца |
| editor | Черновики справочников и валидация | Серверные разрешения, audit |
| admin | Публикация справочников и управление ролями | Сервер, отдельные защищённые endpoints |

В MVP admin/editor UI отсутствует; изменения данных идут через проверенный build/import pipeline. Запрещён переключатель роли в localStorage, который даёт доступ к будущему API. Скрытая кнопка не является контролем доступа. Роль не берётся из импортированного JSON. Editor не получает доступ к личным коллекциям участников по умолчанию.

## Переход к регистрации
После будущего логина показать найденный локальный профиль и предложить его связать/объединить с аккаунтом. Не отправлять коллекцию на сервер до этого действия. guestId не становится auth token. Сервер выдаёт собственный userId, сохраняет ownership, обрабатывает ревизии/конфликты и idempotency. Локальный backup сохраняется до успешной синхронизации. Выход из аккаунта должен чётко определять, остаётся ли локальная копия; это настройка продукта, не случайный побочный эффект очистки store.
