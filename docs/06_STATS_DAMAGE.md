# Статы и калькулятор урона
## Термины
HP — здоровье; SPD — скорость; EA — элементальная атака; PA — физическая атака; ED — элементальная защита; PD — физическая защита. Базовый ранг вида B: Weak1, Moderate2, Strong3, Max4, Elite5. Цвет личного стата C: red1, white2, green3. S+ — все шесть зелёных. RS в этом продукте означает preset: пять зелёных, SPD красный. Это профиль, не новая редкость.

## Формула базового значения
Для уровня L от 1 до 35:
```text
HP = floor(((12 + 2*B + 1.5*C)/5)*L + 10)
Другой стат = floor(((3 + 2*B + 1.5*C)/6)*L + 5)
Итог = базовое значение + бонусные очки + сумма модификаторов реликвий
```

Формула совпала в просмотренном клиентском коде Hub и модели PlayerMiscrit публичного симулятора. Числовые ранги берутся из официального snapshot: у17 семейств они расходятся с Hub, поэтому наши результаты для них намеренно могут отличаться от его старой таблицы. Это существенно сильнее догадки по одной картинке, но всё ещё не проверка исходников игрового сервера. Временные бафы/дебафы передаются отдельным слоем после исходного профиля. Не терять оригинальные значения при ручном редактировании.

## Проверочный пример Flue
Уровень35, S+, без бонусов, без реликвий:
| Стат | Ранг | Расчёт | Результат |
|---|---|---|---|
| HP | 3 | floor((12+6+4.5)/5*35+10) | 167 |
| SPD | 1 | floor((3+2+4.5)/6*35+5) | 60 |
| EA | 1 | та же формула | 60 |
| PA | 4 | floor((3+8+4.5)/6*35+5) | 95 |
| ED | 3 | floor((3+6+4.5)/6*35+5) | 83 |
| PD | 3 | та же формула | 83 |

Красный SPD этого же Flue = floor((3+2+1.5)/6*35+5)=42. Переключение S+→RS не меняет HP/EA/PA/ED/PD. Округляется каждое базовое значение, затем добавляются целые бонусы/реликвии.

Полный бонусный пул на35: 3×34 + 1×34 = 136. Обычная прокачка даёт 102 очка, полная платиновая — ещё34. Для уровня L и p оплаченных повышений модель профиля использует 3×(L−1)+p, 0≤p≤L−1. Разрешить нулевые бонусы для режима сравнения «только база»; обозначать это тестовым профилем, а не полным игровым экземпляром.

## Реликвии
Слоты открываются на10/20/30/35; один предмет на слот подходящего уровня. Нельзя выбирать реликвию35 на уровне20 или складывать пять реликвий. Существующие модификаторы могут быть отрицательными и должны вычитаться. Включённые 75 предметов читать из `data/relics.json`; цены не выводить одной формулой из уровня.

Пример расхождения: Hub Pamboo Cane даёт HP+4, Companion — HP+5. Для этого комплекта выбран Companion. В профиле Flue35 при нулевых бонусах и только этой реликвии получается HP172. Предмет не помещается в неоткрытый слот. Спецэффект реликвии, например иммунитет, не превращать в стат: его учитывает отдельный обработчик или результат объявляет эффект неучтённым.

## Прямой урон: модель Hub
Для положительного прямого удара:
```text
A = PA нападающего, D = PD защитника для физического удара
A = EA нападающего, D = ED защитника для элементального удара
base = AP * A / D * M
perHitMin = floor(base * 0.9)
perHitMax = floor(base * 1.1)
totalMin = perHitMin * hits
totalMax = perHitMax * hits
```

Результат условен: все удары попали, нет критического множителя, щитов, иммунитета и специальных правил. Диапазон не является распределением вероятностей. midpoint=floor((min+max)/2) — середина границ, **не доказанное математическое ожидание**. В UI подпись «Середина диапазона», а не «Средний фактический урон». Не выдумывать равномерное целочисленное распределение из факта наличия границ.

### Таблица стихий
| Атакующая стихия | ×2 против | ×0.5 против |
|---|---|---|
| Fire | Nature | Water |
| Water | Fire | Nature |
| Nature | Water | Fire |
| Earth | Lightning | Wind |
| Wind | Earth | Lightning |
| Lightning | Wind | Earth |

Все другие пары ×1. Физический удар ×1. Для двух **разных** стихий защитника множители перемножаются один раз на стихию. Fire→Nature+Water даёт2×0.5=1. Повторяющиеся элементы запрещены схемой. Флаг Negate в этой модели устанавливает M=1; это не универсальный статус «отменить все эффекты». Не добавлять STAB за совпадение стихии мискрита с ударом: в исследованной формуле его нет.

### Числовые примеры
Flue PA95 против PD83, Mighty Bash AP27: base=27×95/83≈30.9036; min27, max33. При PA120: base≈39.0361; min35, max42. Зачарованный Mighty Bash имеет AP30 по данным: при тех же95/83 — min30, max37. Исцеление10 HP у Mighty Bash не включается в нанесённый урон; если реализован handler, выводится отдельно.

Для AP7, A60, D83, hits3: на удар4–5, сумма12–15. Нельзя сначала умножить base на3, а затем один раз округлить: получится другое правило.

## Попадание, KO, сложные эффекты
Если accuracy отсутствует, показывать результат «при попадании», не считать шанс попадания. Если указано95, хранить95 процентных пунктов; ограничить итоговый шанс до[0,100] только в модуле с подтверждённым правилом модификаторов. Значение accuracy>100 может иметь механическое значение против дебафа: не удалять его из источника. Для точного шанса KO нужны распределение случайного урона, критов, зависимость попаданий и эффекты; этот набор их не подтверждает.

Можно показать оценку количества применений без лечения/промахов: лучший случай ceil(HP/max), гарантированный при минимальном уроне ceil(HP/min), ориентир по середине ceil(HP/midpoint). При min0 гарантированное число отсутствует. Название «применения навыка», а не «ходы до победы»: скорость, смены и пропуски ходов не моделируются.

Реализовать реестр обработчиков: direct, fixed, heal, statModifier, damageOverTime, lifeSteal, immunity, cleanse, special. В первой версии обязательны direct и прозрачная демонстрация неучтённых эффектов. Для неподдержанного primary kind не возвращать число через direct. Полноценный PvP-симулятор не заявляется.

Fixed damage требует явно проверенного фиксированного числа. Не использовать AP как fixed amount без доказательства. Способность Special с текстом «30 fixed damage and heals30» может получить ручной variant-specific handler, но его fixture и происхождение добавляются отдельно. За яд/кровотечение/отложенные удары и редкие взаимодействия отвечают явные правила с тестом.

## Требования к форме
Обе стороны: выбор семейства, уровень, S+/RS/Custom, шесть цветов, бонусы, реликвии, рассчитанные статы, ручной override. Override выделен и отключает автоматическую подстановку только выбранного поля. Проверять числа: finite, положительные атака/защита, допустимые HP, AP≥0, целое число ударов≥1. Не превращать нулевую защиту в1 молча; вернуть понятную ошибку.

Переключение навыка сохраняет профиль сторон. Кнопка «Поменять стороны» переносит существа, реликвии и модификаторы и требует заново разрешить навык. Профиль сохраняет rulesVersion и datasetVersion. После обновления данных старый результат помечается рассчитанным по прежней версии, предлагается пересчёт.

## Как применять Enchant
`abilities[].enchant` содержит **приращения**, не готовые абсолютные значения. Для Mighty Bash base AP27 и enchant.ap3 дают30, не3. Отрицательное enchant.ap для ослабления усиливает отрицательный модификатор через сложение. `accuracy` — прибавка процентных пунктов; `times` — дополнительные повторы; `turns` — дополнительная длительность. Если исходная величина отсутствует, неизвестна или является нормализованным sentinel, не заменять её нулём для сложения.

`enchant.additional` — отдельные добавленные эффекты. Это не простое изменение AP основного удара. Например, случайный дополнительный Attack со своей accuracy нельзя превратить в гарантированный hits+1. Сохранять его как условный эффект. Для списка тегов расширенный поиск учитывает объединение базовых и зачарованных эффектов; в карточке явно видно, что конкретный эффект появляется только после зачарования. Префикс отрицательного Buff нормализуется как Debuff по AP внутри самого эффекта.

`examples/ability-rules.cjs` показывает безопасное получение итоговых числовых параметров без изменения источника. Обработчики статусов остаются отдельным модулем. Неподдержанная дополнительная механика делает результат partial даже при поддержанном прямом ударе.
