## Метод получения
Официальный JSON и открытые JSON/JS Hub прочитаны как публичные ресурсы. Companion исследован через отрисованный DOM: наличие дней определялось по available/unavailable CSS-классам, а не по тому, что буква дня просто присутствует. Координаты прочитаны из left/top маркера. Поэтому понедельник/вторник не перепутаны с одинаковой буквой T в четверг.

Карты доступны браузеру, но прямое скачивание из среды получения возвращало отказ. Включены растры из браузерного отображения, обрезанные до границ изображения. Исходное полное разрешение зафиксировано отдельно. Неполученные original bytes не замаскированы скриншотом с названием original. На карте нет персональных данных.

Пакет simulator прочитан без исполнения стороннего приложения. PCK-directory и GDScript tokenizer buffer разобраны по открытому формату Godot; зашифрованные ресурсы не обходились. Параметры восстановлены из Server/PlayerMiscrit/Constants. Сохранены собственное описание правил и отдельная реализация, а не весь чужой клиент. Godot tokenizer format reference: https://github.com/godotengine/godot/blob/4.6/modules/gdscript/gdscript_tokenizer_buffer.cpp

## Разрешённые конфликты
1. Рoster: официальный420, simulator344, Hub335. Канонический список взят из official; все включённые названия Companion сопоставлены. Не делать вывод, что simulator всегда публикует новинки первым: текущий срез этого не доказывает.
2. Найдено 22 расхождения: 17 семейств имеют разные базовые ранги в official/Hub, для них выбраны официальные значения; 5 сопоставленных реликвий имеют разные модификаторы в Companion/Hub, для них выбраны значения Companion. Каталоги реликвий содержат75 и74 предмета соответственно. Файл qa/source-conflicts.json сохраняет обе стороны и решение по каждой записи.
3. Buff с отрицательным AP нормализуется как debuff. Исходный type сохраняется через snapshot, target и sign не теряются.
4. Средняя граница damage Hub не выдаётся за expectation; модель имеет явное имя.
5. Rebonus цены25/60/50/45/50/60 отличаются от старых гайдов. Воспроизводится конкретный исследованный simulator.

## Что остаётся неизвестным
- Точное соответствие RNG/коррекции/цен реальному игровому серверу.
- Распределение случайного множителя урона, критические удары, часть специальных эффектов и порядок их взаимодействий.
- Полные encounter odds, условия доступа по квестам/уровню, все landmark descriptions.
- Точные полигоны зон; их нет в извлечённой DOM-модели.
- Original-resolution bytes12 карт. Приложены пригодные для автономного просмотра копии меньшего разрешения.
- Минимальный уровень каждой эволюции как отдельный подтверждённый dataset.
- Права на публикацию сторонних ассетов: происхождение известно, лицензия не заявлена.
- Реальный манифест ассетов заказчика: известно, что они у исполнителя будут, но файлы не передавались в эту сессию.

## Как работать с неизвестным без доступа к интернету
UI работает на known-data subset; неизвестное выводит объяснение. Разработчик не обязан искать сайты и не должен изобретать цифры. Для дополнения владелец проекта передаёт versioned JSON/ассеты или подтверждённые контрольные логи. Формат добавления описан в схемах. Сложная способность получает handler только вместе с входным сценарием, ожидаемым результатом и источником.

В документах понятия «проверено» относятся к чтению источника/проверке reference code. Это не означает, что420 мискритов были пойманы или все способности проверены в живом бою. Дата получения не равна дате обновления каждой записи. Статусы provenance нужны именно для этой границы.
